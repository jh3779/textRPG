# 01. 요구사항 (Requirements)

> 인터뷰 영역 4·7 (범위·MVP / 제약·비기능) 정리 · 상태: draft

## 범위 — MoSCoW
| 구분 | 항목 | 근거 |
|------|------|------|
| **Must** | C++ 게임 로직(Game/Map/BattleSystem/Inventory/Quest/Player/Enemy)을 그대로 서버 API로 노출 | DEC-001 |
| **Must** | 5개 지역 이동, 턴제 전투(공격/도망), 인벤토리 조회, 퀘스트 진행이 콘솔 버전과 동일하게 동작 | REQ-F-001~005 |
| **Must** | 저장/불러오기 — 브라우저 `localStorage`에 저장, 재접속 시 이어하기 | REQ-F-006 |
| Should | 데스크톱 기준 레이아웃이 모바일 뷰포트에서도 깨지지 않음(반응형) | REQ-NF-001 |
| Could | 전투/이동 로그를 스크롤 가능한 텍스트 로그로 누적 표시 (콘솔의 연속 출력 느낌 재현) | — |
| **Won't (MVP 제외)** | AI 던전마스터(`ai_service`) 연동 — 위치/전투/승패 동적 서술 | 범위 통제, 다음 단계로 이월 |
| **Won't (MVP 제외)** | 계정/로그인, 서버 DB에 세이브 영구 저장, 멀티플레이 | 개인 학습 프로젝트 규모에 불필요 |

## 비기능 요구사항 (REQ-NF-*)
| ID | 항목 | 기준 |
|----|------|------|
| REQ-NF-001 | 플랫폼 | Web, 데스크톱 브라우저 우선 설계 + 모바일 뷰포트에서 레이아웃 붕괴 없음(반응형) |
| REQ-NF-002 | 오프라인 | 서버(게임 로직 API)가 떠 있어야 플레이 가능 — 완전 오프라인은 지원하지 않음(MVP 범위 밖) |
| REQ-NF-003 | 프라이버시/규정 | 개인정보 수집 없음. 저장 데이터는 브라우저 localStorage에만 존재(서버에 영구 저장 안 함) |
| REQ-NF-004 | 성능/응답성 | 선택지 클릭 → 다음 화면 표시까지 1초 이내(로컬/저지연 배포 기준) |
| REQ-NF-005 | 접근성 | 키보드만으로 모든 선택지 조작 가능, 텍스트 대비 WCAG AA 이상 |

## 제약
- 기술 스택: 게임 로직은 기존 C++(Game/Map/BattleSystem 등)을 최대한 재사용해 서버(API)로 노출. 웹 프론트엔드는 별도 신규 구현(순수 클라이언트, 게임 로직 이중관리 없음). 트랜스포트는 턴 기반 요청-응답 특성상 WebSocket 없이 REST HTTP로 충분(DEC-002).
- 세션: 서버가 진행 중 게임 상태를 세션 단위로 메모리에 들고 있고, "저장"은 그 상태를 직렬화해 클라이언트(localStorage)로 내려주는 방식 — 기존 `saves/save1.txt`의 key=value 필드(hp, max_hp, attack, defense, level, experience, gold, location, game_round, armory_looted, goblin_defeated)를 그대로 재사용(DEC-003). 정확한 API 엔드포인트 형태는 설계 단계에서 확정(OQ-001).
- 일정/예산: 개인 학습 프로젝트, 정해진 마감 없음.
- 되돌릴 수 없는 동작: 새 게임 시작 시 기존 저장 데이터 덮어쓰기 확인 필요(콘솔 버전에는 없던, 웹이라 생기는 신규 고려사항 — OQ-002).
