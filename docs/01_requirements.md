# 01. 요구사항 (Requirements)

> 인터뷰 영역 4·7 (범위·MVP / 제약·비기능) 정리 · 상태: draft

## 범위 — MoSCoW
| 구분 | 항목 | 근거 |
|------|------|------|
| **Must** | 기존 5개 지역(입구/갈림길/무기고/통로/보스방) 던전을 그대로 유지, 시각(초상화·배경 프레임)만 강화 | DEC-101 |
| **Must** | 직업 2~3개 중 선택해 시작 — 직업별로 시작 HP/공격력/방어력만 다르고, 전투 시스템 자체는 콘솔 버전과 동일 | REQ-F-101, DEC-102 |
| **Must** | 전투·탐색 화면을 초상화/텔리지 UI로 시각화 (캐릭터·적 아트는 정지 이미지 수준, 실시간 애니메이션 없음) | REQ-F-102 |
| **Must** | 인벤토리·퀘스트 진행·저장/불러오기가 콘솔 버전과 동일하게 동작 (직업 정보 포함해 저장) | REQ-F-103~105 |
| Should | 전투 로그가 콘솔 버전처럼 텍스트로도 함께 남아, 시각 정보와 텍스트 서술을 같이 제공 | — |
| Could | 승리/패배/레벨업 시 짧은 UI 연출(페이드, 흔들림 등) | — |
| **Won't (이번 범위 제외)** | 사용자가 세계관/스토리 파일을 업로드하면 AI가 그 세계관으로 게임을 생성하는 기능 | 00_project_brief 10-star 비전 — 범위 통제 |
| **Won't (이번 범위 제외)** | 멀티플레이(파티 동시 접속) | 네트워킹은 완전히 별도 트랙의 작업 — 싱글플레이 완성이 먼저 |
| **Won't (이번 범위 제외)** | 새 세계관/새 던전 콘텐츠 제작 — 기존 던전 세계관만 재사용 | 콘텐츠 제작량 통제 |
| **Won't (이번 범위 제외)** | 직업별 고유 스킬트리·성장 분기 | 직업 시스템은 "시작 스탯만 다름" 수준으로 한정 (DEC-102) |

## 기능 요구사항 (REQ-F-*)
| ID | 요구사항 | 우선순위 | 관련 SCR/FLOW |
|----|----------|:--------:|---------------|
| REQ-F-101 | 사용자는 새 게임 시작 시 2~3개 직업 중 하나를 선택하고, 그 직업의 시작 스탯으로 플레이를 시작한다 | Must | FLOW-101 · SCR-002 |
| REQ-F-102 | 탐색·전투 화면에서 캐릭터/적 초상화, HP·MP(있다면) 바가 텍스트 설명과 함께 표시된다 | Must | SCR-003 · SCR-004 |
| REQ-F-103 | 사용자는 콘솔 버전과 동일한 5개 지역을 이동하며, 인벤토리·퀘스트 진행을 확인할 수 있다 | Must | FLOW-102 · SCR-003·005·006 |
| REQ-F-104 | HP가 0이 되면 게임 오버, 던전 수호자를 처치하면 승리 화면으로 전환된다 | Must | FLOW-102 · SCR-007·008 |
| REQ-F-105 | 사용자는 안전 지점에서 저장할 수 있고, 다음 실행 시 선택한 직업을 포함해 이어할 수 있다 | Must | FLOW-103 · SCR-001 |

## 비기능 요구사항 (REQ-NF-*)
| ID | 항목 | 기준 |
|----|------|------|
| REQ-NF-101 | 플랫폼 | Unity, Windows/Mac 데스크톱 스탠드얼론(.exe/.app), 키보드+마우스 |
| REQ-NF-102 | 오프라인 | 완전 오프라인 동작 (서버 의존 없음 — 웹 버전과 달리 로컬 실행 파일이므로) |
| REQ-NF-103 | 저장 데이터 | 로컬 파일(Unity `Application.persistentDataPath`)에 JSON으로 저장, 외부 전송 없음 |
| REQ-NF-104 | 성능 | 정지 이미지 수준의 UI라 별도 성능 목표 없음 — 씬 전환 1초 이내 |
| REQ-NF-105 | 접근성 | 키보드만으로 모든 선택지 조작 가능 (콘솔 버전의 숫자 입력 습관 유지 — 단축키 1/2/3) |

## 제약
- 기술 스택: Unity(버전은 구현 착수 시 최신 LTS로 확정 — OQ-101), UI는 uGUI 또는 UI Toolkit(구현 단계에서 선택), C#으로 게임 로직 재작성(DEC-103 — C++ Game 클래스를 그대로 호출할 방법이 없어 로직을 C#으로 다시 구현하되, 수치·확률·분기는 원본과 동일하게 포팅).
- 아트 자산: 초상화·배경은 이번 범위에서 플레이스홀더 또는 최소한의 자체 제작으로 충당 — 정식 일러스트 외주는 범위 밖.
- 일정/예산: 개인 학습 프로젝트, 정해진 마감 없음.
- 되돌릴 수 없는 동작: 새 게임 시작 시 기존 세이브 덮어쓰기 확인 필요 (웹 버전 기획 때와 동일한 미해결 항목, OQ-102로 이월).
