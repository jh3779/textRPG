# 게임용 깃펜 애니메이션 — 영상·VFX 이미지 제작 목록

작성일: 2026-09-09

## 0. 목적과 기준안

양피지 위에서 깃펜이 글을 쓰는 연출을 실제 게임에 적용하기 위한 이미지 제작·수집 목록이다. 특정 게임 또는 엔진의 확정 사양은 아니다.

이전 `quill_parchment_reference.md`(2026-09-07)는 배경·화면 구조·미술 문법에 중심을 두었다. 이번 문서는 깃펜 움직임, 펜촉 접점, 잉크 생성과 번짐, 독립 합성 레이어에 집중한다.

기준안은 **고정 카메라의 양피지 UI + 손 없이 움직이는 깃펜 + 검정 또는 짙은 갈색 잉크**다. 손이 보이는 연출 또는 자유롭게 회전하는 3D 카메라를 선택하면 추가 자산 설계가 필요하다.

아래 해상도와 수량은 1920×1080 화면을 출발점으로 한 제안이다. 실제 화면에서 보이는 크기와 목표 플랫폼에 맞춰 조정한다. 이 파일은 **제작 목록**이며, 아래에 이름이 적힌 신규 이미지나 애니메이션 파일이 생성되었다는 뜻은 아니다.

## 1. 영상과 실시간 VFX의 구분

| 적용 목적 | 제안 방식 | 제작해야 할 것 |
|---|---|---|
| 항상 같은 제목·서명·로고가 나타나는 인트로 | 고정 영상 또는 이미지 시퀀스 | 장면별 기준 이미지, 고정 글자 레이어, 합성용 분리 이미지 |
| 퀘스트 제목·플레이어 이름·기록 내용처럼 문구가 바뀌는 UI | 실시간 합성 | 깃펜 스프라이트, 그림자, 잉크 브러시, 글자/획 마스크, 이동 경로 |
| 양피지 주변을 카메라가 자유롭게 도는 장면 | 3D 깃펜과 종이 표면을 기반으로 별도 설계 | 3D 모델·재질·애니메이션과 아래 잉크 텍스처 |

초기 검증은 실시간 2D 합성으로 진행하고, 고정 인트로가 필요하면 같은 레이어를 영상 제작에도 재사용하는 방향을 제안한다.

## 2. 실시간 VFX용 이미지 16종

‘종’은 용도 구분이며 실제 파일 수와 다르다. 필수는 최소 시제품에 사용하고, 보강·선택 항목은 후순위로 제작한다. RGBA PNG의 배경은 실제 알파값 0인 투명 영역이어야 한다. 흑백 마스크는 이미지 내용 자체를 제어 데이터로 쓰므로 투명 배경이 필수는 아니다.

## 3. 영상 제작용 기준 이미지 6장

이 여섯 장은 **영상 제작용 장면 기준**이다. 여섯 장만 빠르게 넘기는 완성 애니메이션이나 엔진용 최종 스프라이트 시트를 뜻하지 않는다. 같은 양피지·깃펜·카메라·광원을 유지하고 위치와 작성 진행만 바꾼다.

| ID | 기준 장면 | 이미지에 들어갈 요소 | 제작 시 확인할 점 |
|---|---|---|---|
| V01 | 빈 양피지 | 종이만 놓인 시작 화면 | 글자 배치 영역과 화면 여백을 확정한다. |
| V02 | 깃펜 진입 | 첫 글자 위치를 향해 들어오는 깃펜 | 깃펜이 본문을 과하게 가리지 않게 한다. |
| V03 | 최초 접촉 | 펜촉이 종이에 닿고 잉크 점이 생긴 상태 | 잉크 위치와 펜촉 끝이 일치해야 한다. |
| V04 | 작성 중간 | 일부 획이 생기고 깃펜이 뒤따르는 상태 | 이미 작성된 획은 유지하고 미작성 부분은 숨긴다. |
| V05 | 펜을 들어 이동 | 단어 사이 또는 줄바꿈 구간 | 펜이 들린 동안 연결선이 생기지 않게 한다. |
| V06 | 작성 완료 | 완성된 기록과 종이에서 떨어진 깃펜 | 마지막 획의 정착과 펜의 퇴장 방향을 정한다. |

영상 생성 도구를 쓰더라도 최종 문구는 별도 텍스트·마스크 레이어로 합성하는 제작 방식을 제안한다. 깃펜·종이의 움직임과 정확한 문구를 분리해 수정 범위를 줄이는 목적이다.

## 4. 이미지 외에 함께 준비할 데이터

### 4.1 펜촉 이동 경로

`writing_path.json` 또는 동등한 엔진 데이터에 시간, 종이 좌표, 필압, 펜 접촉 여부를 기록한다. 펜의 이동과 잉크 노출은 같은 경로를 사용한다.

권장 필드: `time`, `page_x`, `page_y`, `pressure`, `pen_down`, `stroke_id`.

글자를 통째로 좌→우로 드러내는 연출과 실제 획순을 따라 쓰는 연출은 서로 다르다. 한글 획순까지 표현하려면 자모와 개별 획의 순서·경로를 별도로 정의해야 한다. 일반 글자 외곽선만으로는 펜을 언제 들고 어느 획을 먼저 쓰는지 결정할 수 없다.

### 4.2 피벗·레이어 규약

깃펜의 회전 기준점은 그림의 가운데가 아니라 **펜촉 접점**으로 잡는다. 포즈마다 캔버스·기준점·크기와 색상을 유지한다. 자동 잘라내기를 사용하는 파이프라인에서는 피벗과 원래 캔버스 오프셋을 보존한다.

아래→위 합성 순서의 제안은 `양피지 → 누적 잉크 → 깃펜 그림자 → 접점 효과 → 깃펜`이다. 접점이 펜촉 위로 덮이는 정도는 실제 시각 검증에서 조정한다.

## 5. 제작·적용 주의사항

**투명도:** ‘흰 배경’ 또는 ‘체커보드가 그려진 배경’은 투명 이미지가 아니다. 알파 채널을 확인한다. 영상 역시 MOV·MP4 같은 확장자만 보고 투명 합성 가능 여부를 판단하지 않는다. 알파를 지원하는 실제 인코딩과 목표 엔진의 재생 경로를 함께 검증한다. 참고: Adobe의 알파 채널 설명 [T01].

**검정 잉크:** 발광 효과용 Additive 합성을 기본값으로 쓰지 않는다. 더하기 합성은 화면을 어둡게 만들 수 없어 검정이 잉크처럼 남지 않는다. 검정색과 불투명도 마스크를 사용하는 합성부터 검증한다. 참고: Epic Games의 Material Blend Modes [T02].

**포즈 일관성:** 깃펜의 각 프레임을 서로 독립적인 새 디자인으로 만들지 않는다. 기본 이미지를 승인한 뒤 변형·리깅 또는 수작업 보정으로 연결한다. 캔버스와 펜촉 정렬을 검사한다. 피벗 편집의 예시는 Unity Sprite Editor 문서 [T03]에서 확인할 수 있다.

**스프라이트 시트:** 처음부터 모든 파츠를 합친 큰 시트 한 장만 만들지 않는다. 독립 PNG를 먼저 검증하고 필요한 프레임만 아틀라스로 묶는다. 프레임 수와 해상도는 목표 플랫폼의 메모리·화질 테스트 후 결정한다.

**가독성과 타이밍:** 펜이 움직이는 경로가 글을 가리지 않게 배치한다. 펜을 든 구간에서는 잉크 생성을 중단한다. 스킵 입력 시 글자를 즉시 완성하고 펜·번짐 효과의 상태도 함께 정리하는 동작을 권장한다.

## 6. 먼저 만들 최소 세트

Q01 기본 깃펜 1장, Q04 그림자 1장, Q05 접촉점 1장, I01 잉크 브러시 3장, I02 번짐 마스크 1장, I06 최종 글자 마스크 1장, P01 빈 양피지 1장.

**7종·총 9장 + 이동 경로 데이터 1개**로 첫 시제품을 만든다. 이 수량은 고정 문구 1개 기준이며 동적 텍스트 렌더링으로 I06을 대체하면 정적 파일 수가 달라진다.

첫 시제품의 합격 기준은 ‘펜촉과 글쓰기 위치가 맞는가’, ‘이미 쓴 잉크가 유지되는가’, ‘펜을 들어 이동할 때 불필요한 선이 생기지 않는가’, ‘완성 문구가 정확하고 읽히는가’다. 깃털의 미세한 흔들림과 큰 잉크 튐은 이후 단계에서 추가한다.

### 라이선스 메모

CC0는 저작권 범위에서 상업적 복제·수정·배포를 허용하지만, 제3자 권리의 무조건적인 보증은 아니다 [L01]. CC BY 3.0 자산은 저작자, 작품명, 출처, 라이선스 링크와 파생 수정 사실 등 조건을 유지한다 [L02].

Texturelabs는 완성 게임의 장면·메뉴·레벨에 사용하는 것을 허용하지만 원본 소스 재배포·에셋팩/템플릿 제작 등을 제한한다. 또한 텍스처를 AI 이미지 생성의 학습 또는 보조에 사용하는 것을 금지한다고 명시한다. 따라서 **영상 생성 모델의 입력/참조용으로는 R06을 사용하지 않는 방향**을 제안한다 [L03].
